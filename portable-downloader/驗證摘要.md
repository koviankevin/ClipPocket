# ClipPocket v0.5.2 本機驗證

日期：2026-10-28（Asia/Taipei）。預設儲存方式改為「透過瀏覽器下載管理員」，也可選「直接存到指定資料夾」。

## v0.5.2 網址與讀取回饋驗證

不含前綴的支援平台網址自動補上 HTTPS；保留通訊協定、網域、帳密與連接埠檢查。讀取中的提示、輸入錯誤及非同步解析失敗都在網址欄下方顯示；舊的輪詢回應不會覆蓋新一次讀取。測試涵蓋手機視窗、修正後重試、畫質選單及略過讀取資訊直接下載，見 tests/url-feedback.cjs 與 evidence/url-feedback-report.json。另以使用者提供的 Facebook Reel 實際驗證 MP4 與聲音完整解碼；私人測試檔及權杖不打包。

## v0.5.1 預設瀏覽器驗證

恢復透過 Windows 網址開啟器啟動預設瀏覽器，不傳入獨立設定檔或啟動瀏覽器控制連線。隔離啟動測試涵蓋初次開啟、重複開啟共用本機服務、不建立專用設定檔、保留舊專用資料及關閉本機服務。見 tests/default-browser.cjs 與 evidence/default-browser-report.json。

## v0.5.1 自動關閉分頁驗證

真正使用瀏覽器測試：工具分頁自動關閉後本機程序與連線亦結束，其他無關分頁保留；有瀏覽歷史而被瀏覽器拒絕關閉的分頁，仍顯示清楚的完成畫面與 Ctrl＋W 提示。關閉請求遭拒時，工具及分頁均保持運作，錯誤原因可見。測試原始碼見 tests/tab-close.cjs，紀錄見 GitHub 的 evidence/tab-close-report.json。

## v0.4.1 可讀性與關閉驗證

主按鈕、輸入欄及選項至少 16px，說明至少 14px；桌面、850px、390px 及 320px 無水平溢出。真正點擊關閉按鈕後，確認本機程序與連線結束，工作畫面被完整的關閉完成畫面取代；另測試狀態刷新仍在進行時關閉，不會覆蓋完成畫面。紀錄與測試原始碼見 GitHub 的 evidence/interface-report.json 及 tests/interface-lifecycle.cjs。

## v0.4 自動更新驗證

啟動時及開啟期間每六小時自動檢查正式 Release；手動檢查與一鍵更新使用相同流程。先串流下載並核對 GitHub SHA-256，再由獨立更新程式驗證 ZIP 路徑、完整檔案清單與各檔案雜湊，才關閉舊版及替換程式。

隔離的本機測試版本涵蓋成功更新並重開、新版啟動失敗後還原舊版、下載雜湊不符、保護設定資料夾與使用者檔名碰撞。核對設定、下載紀錄、已儲存影片與自建檔案保持原樣；測試版本不會發佈到 GitHub。紀錄見「更新驗證.json」。

v0.4 另重新執行三平台瀏覽器實際存檔與完整解碼，沿用以下儲存、畫質及平台限制。v0.3 或更舊版本需先下載新版一次；僅新版之後的更新才能使用工具內的一鍵更新。

更新時請先完成瀏覽器儲存；關閉舊版會清除此次瀏覽器暫存。一般更新失敗會嘗試還原，強制關機、拔除磁碟或權限變更可能需要利用保留的備份手動復原，不宣稱可處理所有斷電狀況。

## v0.3 儲存功能（v0.4 已回測）

實際使用 Windows 免安裝啟動器與乾淨的 Edge 測試瀏覽器，不使用登入帳號或 Cookie：

- YouTube MP4、Facebook MP4、Bilibili MP4／MP3：由網頁點擊開始，完成處理後自動觸發真正的瀏覽器下載事件，檔名符合成品檔名。
- 瀏覽器存出的檔案與本機暫存逐位元組相同，並且從頭到尾完整解碼通過。
- 「再次儲存到瀏覽器」重用處理好的暫存；重新開啟頁面不會自行重複下載舊紀錄。
- 部分內容 HTTP Range、HEAD、Content-Disposition UTF-8 中文檔名、錯誤範圍、失效／無效連結、來源與 API 身分檢查均有測試。
- 下載串流中斷後保留暫存供重試；傳送中不允許關閉工具清除檔案。
- 改選「直接存到指定資料夾」後，實際下載 YouTube MP3，未觸發瀏覽器下載，檔案完整解碼通過。
- 關閉工具後，瀏覽器暫存會清除；直接存到指定資料夾的成品仍保留。
- 桌面與 390px 窄視窗檢查；沒有瀏覽器 JavaScript 錯誤。

瀏覽器模式以檔案串流傳送，不先建立整支影片的網頁 Blob，因此不會把大型成品全部放入網頁記憶體。網頁顯示來源下載與處理進度；瀏覽器下載清單顯示最後接收成品的進度。網頁無法確認使用者是否取消另存或最終存到哪裡，因此只顯示「可交給／交給瀏覽器儲存」，不宣稱瀏覽器已完成存檔。

瀏覽器儲存位置、詢問另存、同名處理、重試與續傳政策依瀏覽器設定。暫存保留至工具關閉；工具運行中且連結有效時，HTTP 端點支援部分內容續傳，不保證各瀏覽器會自動續傳。瀏覽器暫存紀錄不寫入永久下載歷史。

原始 v0.3 紀錄見「瀏覽器儲存驗證.json」。以下保留 v0.2 的平台、畫質與資料夾視窗驗證；新版本沿用相同引擎、畫質選擇與 Bilibili 相容橋接。

## 畫質選擇

改成「最佳可用畫質」或影片實際提供的解析度＋幀率。測試片的選單列出 144p、240p、360p、480p、720p、1080p、1440p、2160p，包含 60fps；不顯示影片沒有的假選項，不放大原片。

選定某個解析度與幀率後，只在同一組來源格式間選擇，不會因偏好 H.264 而默默降到較低解析度。已有針對此情形、8K 選擇邏輯、直式影片與舊格式的測試。

- 相容模式：必要時轉成 H.264＋AAC，保留來源尺寸與幀率。
- 保留來源編碼：只封裝／合併，避免重新編碼；可能需要支援 AV1／VP9 的播放器。

實際 4K60 媒體驗證：下載 Blender 官方影片開頭 3 秒，得到 3840×2160、60fps、AV1＋AAC 的 MP4，完整解碼通過。這是實際片段下載，沒有宣稱已完整下載整支 10 分鐘的 4K 影片。詳見「4K片段驗證.json」。
